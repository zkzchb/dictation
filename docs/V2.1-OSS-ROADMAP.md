# Dictation v2.1 OSS 路线图

v2.1 的目标是把 v2.0.0 整理为可信、可复现、便于贡献的公共开源程序。长期结构由两个
独立仓库组成：稳定程序仓库 `dictation` 与持续增长的内容仓库 `dictation-content`。

## 发布原则

1. `v2.0-stable`、`v2.0.0` 和 `v2.0.0-offline.1` 保持不变，继续作为回滚基线。
2. v2.1 在 `codex/v2.1-oss` 开发，通过候选版门槛后合并 `main`。
3. 程序只保留 V2（FastAPI/SQLite）与 V3（Workers/D1），V1 退出当前产品线。
4. 教材数据和本人录音进入独立内容仓库，使用 content-pack v1 与程序组合。
5. 程序与内容分别版本化；部署必须记录程序版本、内容版本、pack id 和 dataset digest。
6. 每个发布结论必须有自动化检查或真实部署记录支持。

## 双仓库边界

| 仓库 | 变更节奏 | 内容 |
|---|---|---|
| `zkzchb/dictation` | 稳定、低频 | V2、V3、公共前端、选词引擎、内容包规范、部署与测试 |
| `zkzchb/dictation-content` | 持续增长 | 自制教材 JSON、录音清单、本人录音、内容说明与独立版本 |

程序仓库的测试 fixture 只用于验证 schema 和算法，不作为正式教材发布。内容仓库可以包含
多个 pack；只要 `schema_version=1`，新增或修订内容无需修改程序代码。

## 完成定义

程序仓库当前 tree 不再携带正式教材或音频；内容仓库能独立发布与增长；V2/V3 能从同一
外部 pack 启动；三个部署目标各有一次可复现成功记录；CI、依赖审计、升级和回滚通过；
新贡献者能够仅凭公开文档完成安装、测试和第一个 Pull Request。
