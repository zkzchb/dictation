## 主要阻塞项

### 1. 内容权利与许可证

当前 `README.md` 明确把内容描述为“人教版小学语文三年级上册”，历史提交说明中出现
“照抄印刷拼音”等来源描述。AGPL-3.0 能覆盖维护者有权许可的程序代码，但不能自动授予
第三方教材数据或 TTS 生成音频的再分发权。公开仓库前必须拆分代码与内容许可，并移除或
隔离权利基础不清楚的内容。

### 2. 运行时仍绑定单一教材包

默认路径、课程号、冷启动课、首课、课程数量、知识点数量和音频数量分散硬编码在 Python、
Shell、测试与文档中。虽然已经支持 `DICTATION_CONTENT_ROOT` 的部分入口，但当前还不是
真正的内容包驱动产品。

### 3. 开源项目工程不完整

仓库缺少贡献指南、安全政策、行为准则、Issue/PR 模板和通用发布流程；现有 workflow
仍以 v2.0 冻结与提交消息触发为中心。Issues 关闭且主分支未保护，不适合接收外部贡献。

### 4. 公开历史尚未审计

当前快照没有明显密钥不等于历史安全。公开前需要扫描全部分支、标签和可达提交中的文件，
尤其是曾经提交的本地说明、环境文件、部署配置、原始词表和设计文档。若无法在不破坏项目
可验证性的前提下净化现有仓库，应保留私有档案并发布经过审计的 OSS 仓库。

## 当前结论

v2.0 是可用且经过冻结的产品基线，但还不能直接把仓库切换为 public。v2.1 应优先完成
内容包抽象和公开发行边界，再完善贡献与发布工程。此顺序既保护现有可部署版本，也能让
Codex for Open Source 申请展示真实的维护工作，而不是一次仅修改 README 的包装发布。
