## 主要阻塞项

### 1. 内容权利与许可证

当前 `README.md` 明确把内容描述为“人教版小学语文三年级上册”，历史提交说明中出现
“照抄印刷拼音”等来源描述。AGPL-3.0 能覆盖维护者有权许可的程序代码，但不能自动授予
第三方教材数据或 TTS 生成音频的再分发权。公开仓库前必须拆分代码与内容许可，并移除或
隔离权利基础不清楚的内容。

### 2. 运行时仍绑定单一教材包

默认路径、课程号、冷启动课、首课、课程数量、知识点数量和音频数量分散硬编码在 Python、
Shell、测试与文档中。虽然已经支持 `DICTATION_CONTENT_ROOT` 的部分入口，但当前还不是
真正的内容包驱动产品。

### 3. 开源项目工程不完整

仓库缺少贡献指南、安全政策、行为准则、Issue/PR 模板和通用发布流程；现有 workflow
仍以 v2.0 冻结与提交消息触发为中心。Issues 关闭且主分支未保护，不适合接收外部贡献。

### 4. 公开历史审计结果

已扫描 `main` 与 `main-offline` 的 101 个唯一提交和 244 个唯一文本 blob。扫描没有发现
真实 API key、访问令牌、私钥或明文生产口令，匹配项均为环境变量读取或占位符。但历史中
仍存在三类不应公开的内容：

- 已删除的 `CLAUDE.md` 包含未成年人的称呼和年级信息；
- 已删除的本地部署脚本包含个人私网地址；
- 历史 xlsx、教材 JSON 和提交说明记录了从印刷教材整理词表与拼音的过程。

这些内容通过主线历史可达，单纯在 v2.1 新提交中删除并不能阻止公共仓库访问旧提交。
现有仓库因此不直接改为 public，也不为保留 PR 数量而承担隐私和内容权利风险。

## 公开仓库策略

1. 当前 `zkzchb/dictation` 保持私有，作为 v1/v2/v3 原始工程档案和 v2.0 部署来源。
2. v2.1 在私有 `codex/v2.1-oss` 分支完成重构和验证。
3. 候选版通过后，以经过审计的 v2.1 tree 建立干净历史的公共 OSS 仓库；不复制旧 Git
   对象、教材数据、音频或私人部署信息。
4. 公共仓库增加 `HISTORY.md`，用不含私人信息的方式总结 29 个 PR 所形成的选词、录音、
   数据安全、离线发行和三目标部署经验。
5. 原始仓库与公共仓库之间只通过明确的发行导出流程同步，禁止直接 mirror。

## 当前结论

v2.0 是可用且经过冻结的私有产品基线。现有仓库将保持私有；v2.1 优先完成内容包抽象和
公开发行边界，再完善贡献与发布工程，最终从审计过的 tree 建立干净公共仓库。此顺序既
保护现有可部署版本和私人信息，也能让 Codex for Open Source 申请展示真实的维护工作，
而不是一次仅修改 README 的包装发布。
