## 1. 产品定位

为一名小学生（Mia）定制的中文听写练习应用。核心闭环：

```
选课 → 生成词表 → 播放听写 → 人工核对对错 → 记分入库 → 错词进入下次复习
```

单用户 MVP（user_id 固定为 1），无需注册登录。人教版语文教材，学期切换时整体换库。

设计原则：
- **考的是字词的掌握，不是应试**：生字听写考"字"，用组词承载；错词优先复现。
- **不超纲**：任何一次听写只出现当前课或已学过的内容。
- **人工核对**：判分由家长/学生点击卡片完成，服务端只做记录与算分，不做自动识别。
- **三版本对照**：同一套题库和音频，三种部署形态并行，用于对比技术方案。

## 3. 数据模型

六张表。静态字典表（lessons/knowledge_points）由 xlsx 转换灌入；动态记忆表（其余四张）随使用增长。

```
lessons              课程目录
  lesson_seq PK      = xlsx 的 lid（如 3111）
  unit_id            = lid // 10（如 311）
  unit_name, lesson_name

knowledge_points     知识点（听写的最小单位）
  id PK AUTOINCREMENT
  lesson_seq FK
  target             生字为单字（坡）；词语/易错为整词；多音字为单字
  category           {生字, 词语, 易错字, 多音字}   ← 只存粗类
  options_json       [{text, pinyin}] 组词候选；
                     多音字为 [{text,pinyin,pron}]；
                     细分类型(vtype)存于此，不进 category

user_progress        当前进度（单用户）
  user_id PK, current_lesson_seq, updated_at

user_memory          字词掌握度（掌握态，非选词驱动，见§6）
  user_id, kp_id, status, error_count, correct_streak,
  last_tested_date, next_review_date, UNIQUE(user_id,kp_id)

dictation_history    每次听写会话
  id PK, user_id, dictation_type{daily|unit}, scope_id(lid), score, created_at

dictation_items      会话内每个词的对错  ← 选词引擎的核心依据
  id PK, history_id FK, kp_id, is_correct
```

### 关键设计决定

**① category 只存粗类 4 种。**
vocab 的 22 种细分（AABB式/含数字/成语…）存进 `options_json` 的附加字段，不塞进 `category`。这样选词算法可以简单地按 {生字/词语/易错字/多音字} 过滤，而"高阶词 vs 普通词语"的区分改用 lid 判定（复习课自身 vocab = 高阶词，子课 vocab = 普通词语）。

**② 错词是"字级/词条级"的，记在 kp_id 上。**
`dictation_items` 记 kp_id。生字的 kp 是"字"（坡），所以错词重考时重考这个字，`generate_daily` 会重新随机取它的组词——本次"山坡"、下次可能"坡地"。符合"考字"的意图。

**③ score 用 REAL。** 旧库曾用 INTEGER 导致精度丢失，新库统一 REAL。

**④ 分数由服务端算。** 前端只上报每个词的 is_correct，服务端计算 `correct/total*100` 并写库，前端无法伪造分数。

## 4. 词库与编号方案

编辑源是 `wordlist_template.xlsx`，6 张表，用编号编码层级，一个 ID 自解释年级/学期/单元/课/类型/序号。

| 表 | 主键 | 编号规则 | 说明 |
|---|---|---|---|
| unit | uid | 311 = 3 年级/1 学期/1 单元 | 单元 |
| lesson | lid | 3111 = ...1 单元/1 课；末位 0 为复习课；3000 冷启动 | 课程 |
| word2write | wid | 后两位 01–49 | 生字，每字 ≤2 组词 |
| vocab | vid | 后两位 51–79 | 词语/成语，含 vtype 细分 |
| polyphonic | ppid | 后两位 81–99，同 ppid 多行=多读音 | 多音字 |
| typo | tid | lesson 3000 或各单元复习课下 | 形近易混字对 |

派生关系：`lesson_seq = lid`，`unit_id = lid // 10`，`lesson_seq = 各表ID // 100`。

**词库现状（实测，拼音已补全，外键合法）**：
- 43 课（34 正式 + 8 复习 + 1 冷启动），250 生字，418 词语，54 易错，39 组多音字
- **去重后 903 条唯一词** = 需录音/TTS 的切片总数

### 转换产物

`convert_wordlist.py` 读 xlsx → 输出：
- `shared/data/lessons_*.json`：课程目录
- `shared/data/kp_*.json`：知识点（category 粗类 + options_json）
- `shared/web/studio_manifest.json`：待录音清单（去重后的唯一词，按 MD5[:12] 命名）

**去重原则**：同一个词只录一份音频（按文本 MD5 命名），跨课重复自动共享同一音频文件。

## 5. 选词引擎

完整细则见 [听写选词规则.md](听写选词规则.md)，此处只列接口契约与算法骨架。

**两种模式**：
- 生字听写（正式课）：30 词判分 + 末尾 2 个多音字（仅播报、不判分）
- 单元复习（复习课）：50 词

### 接口契约

```
GET /api/generate_daily/{lesson_seq}?mode={daily|unit}
→ {
    "data": [ {id, target, pinyin, word_type, audio_url?}, ... ],   # 30 或 50
    "polyphonic_section": [ {character, readings:[{pron,example_word,example_pinyin}]}, ... ]
  }
```
- `word_type` ∈ {new_char, new_word, wrong, review}，仅用于前端配色。
- `audio_url` 仅 V2/V3 返回（预录切片路径 `/audio/w/{hash}.mp3`）；V1 不返回，改由 `/api/generate_audio` 实时合成。
- `polyphonic_section` 仅 daily 模式返回，unit 模式为空。

```
POST /api/submit_dictation
  body: { dictation_type, scope_id, results:[{kp_id, is_correct}] }
→ { status, score, correct, total }
```

### 生字听写取词骨架（7 级梯队）

```
target = 30
picked = []  ; seen_text = set()  ; seen_char = set()

def push(kp):                       # 去重后加入
    text = 选词(kp)                 # 生字随机取 word1/word2，其余取第一个
    if text in seen_text: return
    if kp是生字 and kp.target in seen_char: return   # 同字不重复
    picked.append(...) ; 记录 seen

梯队1 上次错词(全部)   ← dictation_items: 最近一次 history 的 is_correct=0
梯队2 本课 vocab
梯队3 本课 word2write
梯队4 前2-4次错词       ← 倒数第2-4次 history 的错词，按 error_count 降序
梯队5 前1-3课 word2write
梯队6 前1-3课 vocab
梯队7 继续向前回溯(可跨单元) 直到 len(picked)==30
# lid==3111 时，在梯队4位置插入 lesson3000 易混字(冷启动)
```

### 单元复习取词骨架（3 级梯队）

```
target = 50 ; unit = lid[:3] ; kids = 该单元所有正式课
梯队1 本单元错词(全部)         ← dictation_items 过滤 scope_id 属于本单元
梯队2 kids 的 vocab + word2write
梯队3 本复习课自身的 typo(tw1+tw2成对) + vocab(高阶词)
```

### 约束（两模式通用）

- 一次内不出现重复词；同课生字表∩词语表撞词时（实测 118 处）优先换该生字的另一组词，都撞则该字不单独出题。
- 一个生字一次只出 1 个组词。
- 易混字对（typo 的 tw1/tw2）成对出现，中间至少隔 3 个词。
- 全部来自当前课或已学课，不超纲。

## 6. 复习机制的转变（重要）

**新选词规则与旧 SRS 代码存在实质差异，实现时必须注意。**

旧版 `submit_dictation` 实现了一套间隔重复（SRS）：答对 `correct_streak++`、连对 3 次判"已掌握"、`next_review_date` 按 2ⁿ 天指数退避；出题时按 `next_review_date <= today` 捞到期词。

但**新规则（§5）里没有任何一级依赖 `next_review_date`**。复习通过两个机制实现：

1. **错词重考**（梯队 1、4）：数据来源是 `dictation_items` + `dictation_history`，按"最近第几次会话"定位，不是按日期。
2. **课程回溯**（梯队 5、6、7）：按 lid 顺序往前取最近课程的全部词，做对的词也会被重考（间隔复习，符合预期）。

因此：

- **选词驱动力从"日期"变成"会话序 + 课程序"**。`generate_daily` 应查 `dictation_history`（按 created_at 排序取最近 N 次）+ `dictation_items`（取其中 is_correct=0 的 kp_id），而非查 `user_memory.next_review_date`。
- **`user_memory` 降级为掌握度统计**：仍在 `submit_dictation` 里更新 error_count/correct_streak/status，用于日历、错词本、学情展示，但**不再是选词的输入**。
- **冷启动注入**：lesson 3000 的易混字在 3111 通过"梯队4位置插入"取用，不再依赖 `user_memory` 预注入 + 日期到期的老机制。

> 实现要点：`generate_daily` 需要新增"取最近 N 次会话错词"的查询。SQL 形如
> `SELECT DISTINCT di.kp_id FROM dictation_items di JOIN dictation_history dh ON di.history_id=dh.id
> WHERE dh.user_id=1 AND di.is_correct=0 ORDER BY dh.created_at DESC`，
> 梯队1 取最近 1 次的 history，梯队4 取倒数第 2–4 次。

## 7. 音频方案

同一套词，两条产音线，产物文件名一致（词文本 MD5[:12]），可互换：

| | A 线：TTS 合成 | B 线：真人录音 |
|---|---|---|
| 工具 | `shared/tools/gen_slices.py` | V2 `/studio` 录音工作台 |
| 音源 | 有道 `youxiaoxun`，0.6 倍速 | 家长朗读 |
| 切割 | 逐词单独请求，无需切割 | 批量录一组 → pydub 按静音切割 |
| 产物 | `shared/web/audio/w/{hash}.mp3` | 同左，可覆盖 TTS 版 |

系统提示音（"准备听写""第 N 组""听写完毕"）存 `audio/sys/`。

### 播放方式（V2/V3）

服务端不再拼接大音频，改由**浏览器播放列表驱动**：
`generate_daily` 给每个词附 `audio_url` → 前端排出播放序列（每词报 3 遍，停顿 8s→5s→2s）→ `<audio>` 逐个播、`setTimeout` 控停顿。田字格随播放高亮当前词。好处：无生成等待、停顿可实时调、支持单词重听。

V1 仍走老路：`/api/generate_audio` 用 pydub 拼一个完整 MP3 返回 URL + 时间轴。

### 录音工作台流程（V2 `/studio`）

```
加载 manifest → 提词器显示5词 → 倒计时 → 录音(MediaRecorder)
→ 上传 /api/studio/split → pydub 按静音切割 → 逐词回放核对
→ 确认 → /api/studio/save 存为 {hash}.mp3 → 下一组
```
切割段数 ≠ 词数时提示重录，避免错位。已录词通过 `/api/studio/check` 跳过。

## 8. 前端与交互

单页 Alpine.js + Tailwind（CDN），微信绿配色，移动端布局。状态机 `step` 0→7：

```
0 选模式 → 1 选课 → 2 词表勾选 → 3 生成(仅V1有等待) →
4 播放听写(田字格高亮) → 5 逐词核对对错 → 6 记分 → 7 成长足迹日历
```

**多音字处理**：**不需要独立前端页面**。多音字并入正常听写的播放列表**末尾**，仅通过语音播报（"下面是多音字，请写出不同读音的组词。第一个：好……"）+ 留足书写间隔实现。特点：
- **不判分、不计入每日成绩、不进错题库**（core 30 词才判分入库）
- 核对阶段（step 5）**不列出**多音字，只核对正文 30 词
- 多音字数量少、重复次数多，无论写对写错都会在后续听写中反复出现，靠曝光记忆
- 每次固定 2 个：本课多音字优先，不足或本课无多音字时从已学多音字中轮换补足

因此 `polyphonic_section` 只是给前端"往播放列表末尾追加几个纯语音项"的数据，不触发任何判分/入库逻辑。

**日历/学情**：35 天打卡视窗，`/api/dictation_history` 取区间每日最高分，颜色分档（≥90 绿 / ≥80 浅绿 / <80 红）。

## 11. 年级切换与数据安全

V1 现有 `v1/dictation.db` 含 Mia 二年级下学期（2026-03 起）的真实学习记录。升三年级用**全新库**，不迁移任何历史。

**切换步骤**：
```
1. 备份二年级库：cp v1/dictation.db ~/backup/dictation_grade2_YYYYMMDD.db
2. 备份确认后删除旧库
3. init_db.py 建三年级空库（建表 → 灌三年级 JSON）
4. 冷启动：lesson 3000 的 10 组易混字 + 13 组多音字，供 3111 取用
```

**版本间一律不迁移历史**：V1/V2/V3 各自从空库独立起算学习记录。三个版本是并行对照实验，数据互不相通，这也简化了 D1 与 SQLite 之间本来就无法直接互导的问题。

**红线**：
- 任何脚本测试一律用 `_smoke.db` 副本，绝不碰真实库。
- `init_db.py` 会 DROP 全表，运行前二次确认目标库路径。
- 删除旧库前必须确认备份已生成。
- `*.db` 已 gitignore，不进版本库。
