# Dictation：可运行学习材料基础设施

Dictation 从中文听写出发，但项目的边界不止于一套固定教材或一种练习。它希望成为一套可自托管的学习运行时：程序负责呈现练习、选择条目、播放或录制声音、保存结果与支持复习；可独立发布的学习包提供课程、词条、录音和规则；学习记录由部署者持有，并产生可追溯、可解释的反馈。

> **程序无状态，材料有版本，记录有归属，反馈可解释。**

这里的“程序无状态”不是说运行时不保存任何数据，而是说程序发布物不捆绑某个家庭、学生或班级的专属内容与记录。程序、材料和学习状态应当能够独立升级、迁移和审计。

## 为什么这样设计

面向儿童和课堂的学习工具，常常被固定教材、统一配音和中心化账户体系绑定。但真实教学高度依赖地区、年级、学校、家庭和教师：同一个词可能需要不同的顺序、提示、读法和复习规则；家长或教师的声音有时比标准化合成音更有陪伴感；录音与学习记录也不应默认成为平台集中收集的行为数据。

因此，Dictation 把决定权留给最接近学习者的人：

- 家庭和教师决定学什么、如何组织、使用谁的声音；
- 部署者决定程序、材料、录音和记录放在哪里；
- 开源社区可以审计运行逻辑、复用部署方式并扩展新的学习模块；
- 自动化和 AI 可以辅助维护、质检与反馈，但不能成为不可解释的唯一裁判。

## 四层模型

| 层次 | 职责 | 可独立演进的内容 |
| --- | --- | --- |
| Learning Runtime（学习运行时） | 呈现任务、调度条目、播放音频、记录作答、支持复习 | Web 应用、API、部署适配器 |
| Learning Pack（学习包） | 描述可运行的学习材料 | 课程、词条、稳定 ID、音频、顺序与规则 |
| Learning Ledger（学习账本） | 保存属于学习者的过程与结果 | 进度、错误、复习记录、部署侧身份映射 |
| Studio（材料工作台） | 让家庭和教师制作、校验与维护学习包 | 录音、重录、人工质检、导入与发布流程 |

这四层之间使用明确的格式和稳定标识连接。运行时不应把正式教材重新复制进代码仓库，学习包也不应夹带真实学习记录或部署凭据。这样的边界使代码、内容和数据可以采用不同的版本、授权和发布节奏。

## 当前参考实现

截至 v2.1.0，项目已经提供并验收三类部署路径：

- 本地 Ubuntu 部署，适合家庭内网和开发验证；
- VPS 部署，适合教师工作台或自行管理的服务；
- Cloudflare Workers + D1 部署，适合低运维成本的个人版本。

真实 Caddy 80 端口下的 `/dictation/` 子路径已完成自动化与浏览器人工验收，覆盖首页、课程加载、听写流程、系统与词语音频、Studio、麦克风授权、录音上传、回放和服务重启持久性。

配套的 `dictation-content` 仓库以独立版本发布参考学习包。`content-v1.0.0` 包含 43 课、814 个知识点和 894 个 MP3 文件，并通过清单、校验和与数据集摘要固定其内容身份。它是可运行的参考材料，不是运行时唯一允许的教材。

## 产品形态与面向人群

V2/V3 是技术运行时，下面的 Edition 是面向使用场景的产品形态；两套名称不在同一个层级，也不是一一对应关系。

| 产品形态 | 状态 | 主要使用者 | 当前承载方式与边界 |
| --- | --- | --- | --- |
| 个人练习版（Personal Edition） | 可用 | 个人与家庭 | V3 Workers/D1 是低运维参考方案，V2 本地/VPS 也可承载；当前不等同于具备完整认证体系的多用户服务 |
| 教师工作台版（Teacher Studio Edition） | 核心工作流可用 | 教师与内容维护者 | 当前基于 V2 本地/VPS，覆盖录音、重录和人工质检；更完整的材料导入、编辑和发布体验仍待建设 |
| 班级共学版（Classroom Edition） | 规划中 | 班级、学校与自托管机构 | 预期运行于自托管 VPS 或校内服务器；班级、学生、任务、多教材和教学反馈均不是 v2.1.0 的现有能力 |

开发者和研究者还可以直接复用可审计的学习运行时、内容格式和部署基线。当前发布版覆盖个人练习和教师材料工作流的核心路径；完整多用户认证与班级协作必须继续作为路线图描述。

## 当前能力与路线边界

已经可用并有发布证据的能力包括：版本化课程包、稳定 ID、系统与词语音频、听写和复习流程、录音 Studio、人工质检页面、本地/VPS/Workers 部署，以及带校验和、SBOM 和来源证明的可复现发布流程。

后续可逐步探索：

- 更安全易用的材料导入、录音与发布工作台；
- 多课程包、多用户和自托管课堂模型；
- 可迁移的学习账本与更细致的复习策略；
- 在明确授权与人工复核下使用语音或语言模型辅助发音、拼音和材料质检；
- 将运行时扩展到识字、英语听写及其他由学习包驱动的训练。

这些方向是路线图，不代表已经上线。新增能力仍应服从数据最小化、可解释和可退出原则。

## 开源、自托管与授权边界

运行时代码使用 AGPL-3.0 授权，以保持服务端修改的可回馈性；参考教材包使用 CC BY-NC 4.0，并在内容仓库中独立说明来源与权利。代码授权不会自动覆盖教材、录音或第三方素材，内容授权也不会改变程序代码的许可。

自托管不是要求每位使用者成为运维专家，而是保留可选择性：能够在家庭设备、教师管理的服务器或低成本边缘平台上运行，能够导出和迁移材料与记录，也能够在需要时检查系统究竟做了什么。

## 维护原则与 AI 边界

项目可以使用 Codex 等工具辅助跨语言代码审查、回归测试、部署文档、依赖和安全检查、学习包校验以及发布证据整理。这些工具首先服务于维护者工作流，不等同于已经提供面向学生的 AI 功能。

涉及学习者的判断应尽量基于确定性规则和可检查证据；未来即使引入模型能力，也应保留人工复核、清晰提示、最小数据范围和非 AI 的可用路径。
